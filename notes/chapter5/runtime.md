## 运行时：提交，重放与动态形状

### 主机准备与加速器计算的重叠

### CUDA Graph：提交收益与输入复制开销

为了避免 GPU 反复等待主机准备数据，CUDA Graph 可以让主机每次只需发起一次图重放，不必重新逐个准备和提交 kernel。

图重放前，还需要把新输入放到图所记录的地址。  
典型实现为图预留固定缓冲区，重放时将新输入复制到缓冲区。  
也可以直接写到缓冲区中，省去这一次复制开销。

### 动态形状与编译开销

对于输入行数的变化，运行时有三种方式来应对：

- 通用程序根据当前形状计算索引和边界，编译开销小，但运行时开销大。
- 分桶程序提供少数代表形状，并将输入补齐到选定形状，编译开销与运行时开销适中。
- 特化程序为每个已知形状生成单独的实现，编译开销大，但运行时开销小。

### Persistent Kernel：按数据块调度任务

图重放和程序缓存都减少了主机的重复准备  
但是加速器上还有另一类等待，即 kernel 之间的依赖关系。

persistent kernel 一直驻留在加速器上运行，从队列取出任务，再通过完成标志确认所需数据是否准备好。  
这种安排减少了主机反复 kernel launch 的工作，也让相邻算子可以按块重叠运行。
