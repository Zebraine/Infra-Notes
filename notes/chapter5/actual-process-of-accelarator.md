## 加速器执行过程中的提交，搬移与同步

考虑输入与输出都在 CPU 内存中的矩阵乘，CPU 准备输入，将输入送入 GPU，发起计算，再从 GPU 取回结果的过程。  

### 从框架调用到 kernal launch

通过常见的 PyTorch 调用矩阵乘时，CPU 首先执行框架代码，读取张量形状和数据类型，选择实现，准备地址和参数，再通过运行时与驱动向 GPU 提交任务。  
其中向加速器发起一次 kernal 执行称为 kernal launch。  
运行时负责提交任务，管理内存和同步执行，编译器则事先或在首次调用时生成加速器代码。

这分为三个层次：  
算子描述数学工作，kernal 在加速器上完成这项工作，launch 则是 CPU 发起这次执行的动作。  

CUDA 执行一个 kernal 时会启动多个线程，若干线程组成一个线程块，所有线程块组成一个线程网格。  
矩阵乘通常将输出矩阵分为多个 tile，交给不同线程块计算，块内线程协作读取输入并累加结果。  

kernal launch 采用异步方式，CPU 发起后立即返回，GPU 在后台执行。  
CPU 可以继续执行其他任务，或者等待 GPU 完成计算。

### 主机与加速器之间的数据复制

常见的复制方向有 3 种：
- H2D：从主机内存到显存，例如当前 batch 的输入张量
- D2H：从显存到主机内存，例如计算结果
- D2D：在显存中复制，例如固定输入缓冲，或重排结果

上述的矩阵乘的执行过程是：
CPU 准备输入 -> H2D -> GPU 计算 -> D2H -> CPU 使用结果
