## 加速器执行过程中的提交，搬移与同步

考虑输入与输出都在 CPU 内存中的矩阵乘，CPU 准备输入，将输入送入 GPU，发起计算，再从 GPU 取回结果的过程。  

### 从框架调用到 kernal launch

通过常见的 PyTorch 调用矩阵乘时，CPU 首先执行框架代码，读取张量形状和数据类型，选择实现，准备地址和参数，再通过运行时与驱动向 GPU 提交任务。  
其中向加速器发起一次 kernal 执行称为 kernal launch。  
运行时负责提交任务，管理内存和同步执行，编译器则事先或在首次调用时生成加速器代码。

这分为三个层次：  
算子描述数学工作，kernal 在加速器上完成这项工作，launch 则是 CPU 发起这次执行的动作。  

CUDA 执行一个 kernal 时会启动多个线程，若干线程组成一个线程块，所有线程块组成一个线程网格。  
矩阵乘通常将输出矩阵分为多个 tile，交给不同线程块计算，块内线程协作读取输入并累加结果。  

kernal launch 采用异步方式，CPU 发起后立即返回，GPU 在后台执行。  
CPU 可以继续执行其他任务，或者等待 GPU 完成计算。

### 主机与加速器之间的数据复制

常见的复制方向有 3 种：
- H2D：从主机内存到显存，例如当前 batch 的输入张量
- D2H：从显存到主机内存，例如计算结果
- D2D：在显存中复制，例如固定输入缓冲，或重排结果

上述的矩阵乘的执行过程是：
CPU 准备输入 -> H2D -> GPU 计算 -> D2H -> CPU 使用结果

CPU 在将数据传入 GPU 前吗需要将数据复制到 锁页内存(pinned memory) 中   
这么做会带来额外的一次主机复制。  
如果让 CPU 直接在可复用的锁页内存中准备数据，则可以避免这次复制。

### stream, event 与完成顺序

CUDA 的 stream 是一串按顺序执行的加速器任务。  
如果复制与计算在同一个 stream 中，则它们会按顺序执行。  
如果不在同一个 stream 中，可以通过 event 来指定跨流的执行顺序。

### 一个 kernal 在 SM 中的执行过程

SM 每次将 32 个线程编成一组，一起发射，称为 warp。  
因此一条加载指令需要一次给出 32 个地址。

一个线程块要在 SM 上驻留，需要同时被分配线程槽，寄存器和共享内存。  
占用率指驻留的 warp 数占 SM 最大驻留 warp 数的比例。

每个独立的访存请求都来自驻留的 warp，当在途请求足够多，一个请求等待返回时，接口仍被其他请求占用，这称为延迟隐藏。

一条矩阵乘加指令(MMA)有两种发出方式，warp 级指令由一个 warp 单独发出，操作数需要先放进 warp 的寄存器。  
warpgroup 级指令由 4 个相邻的 warp 联合发出，可以从共享内存取操作数。

在 SM 中，槽已填满与槽已用完这种时刻由 栅栏(barrier) 给出。  
栅栏是一个共享内存中的计数器，用于异步线程之间的同步。

利用栅栏可以实现 warp 间的分工，例如生产者-消费者模式。  
这种分工称为 warp specialization。
