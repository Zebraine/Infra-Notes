## 系统设计的关键数字

### 用数量级判断方案

| 操作                             | 时间(ns)    |
| -------------------------------- | ----------- |
| 一级缓存访问                     | 0.5         |
| 分支预测错误的恢复               | 5           |
| 二级缓存访问                     | 7           |
| 互斥锁加锁与解锁                 | 25          |
| 访问主存                         | 100         |
| Zippy 压缩 1K 字节               | 3,000       |
| 1 Gbit/s 网络发送 2K 字节        | 20,000      |
| 主存连续读取 1 MB                | 250,000     |
| 同一数据中心内的网络往返         | 500,000     |
| 磁盘寻道                         | 10,000,000  |
| 磁盘连续读取 1 MB                | 20,000,000  |
| 发送数据到同一大洲的另一数据中心 | 150,000,000 |

一次磁盘寻道所需时间约为主存的 100,000 倍。

**Amdahl 定律**:

$$
Speedup = \frac{1}{(1 - f) + f / s}
$$

若原执行时间中有比例 $f$ 的部分可以加速 $s$ 倍，则加速比为 $Speedup$。  
所以即使这部分加速到可以忽略，总加速比也无法超过 $1/(1 - f)$。

Amdahl 定律适用于任何只加速部分环节的完整流程。

### 分析 AI 系统需要哪些关键字

设某任务需要同时保存 $M$ 字节，执行 $F$ 次浮点运算，需要向某个存储接口读写 $R$ 字节数据。  
加速器能提供容量 $M_{cap}$，计算吞吐量 $\Pi$，存储接口带宽 $\beta$。

这三个需求和三个能力的关系可以用下式表示：

$$
M \leq M_{cap},\ T_{compute} = \frac{F}{\Pi},\ T_{memory} = \frac{R}{\beta}
$$

若 $\Pi$ 和 $\beta$ 都取峰值，得到的就是所需的时间下界。

理论下界是硬件的物理基线，所以下界与实际耗时 $T$ 的比值，反映了硬件能力的利用率。  
计算利用率 $F/(\Pi T)$ 称为 **MFU** (模型 FLOPs 利用率)  
带宽利用率 $R/(\beta T)$ 称为 **MBU** (模型带宽利用率)

除此之外还有操作延迟需要考量。

**容量**代表能同时放下多少数据，以 bytes 为单位。

**计算吞吐**代表单位时间内能完成的运算量，以 FLOPs 为单位。  
FLOP 表示一次浮点运算，FLOPs 表示运算总次数，FLOP/s 表示每秒浮点运算数。  
GFLOPs, TFLOPs 分别表示每秒十亿次和万亿次浮点运算。  
矩阵计算中，一次乘法和一次加法都算作一次 FLOP。

**带宽**代表单位时间内能传输的数据量。  
显存带宽描述显存与芯片之间的数据传输能力  
卡间链路和网络带宽描述其它路径的能力

**延迟**代表从发起请求到收到响应所需的时间，以秒为单位。

### 参数存储量与链路带宽的换算

第一步是将模型参数换成存储字节数，判断加速器能否放下模型。  
第二步再用字节数除以带宽，估算传输数据所需时间。

以 DeepSeek-R1-70B 为例，模型参数量为 70B，假设每个参数占用 2 字节，则总存储量为：

$$
M_W = Nb_W = 70 \times 10 ^ 9 \times 2\ bytes = 140\ GB
$$

如果使用 H100 SXM 80GB 显卡，需要将模型权重均分在两张卡上。  
**切分**是让不同加速器分别保存并计算模型的一部分，在计算过程中交换中间结果。

也可以改变权重的存储精度。**量化**是用较少的位数表示数值，并用 scale (缩放因子) 来近似还原数值。  
通常每 128 个参数共享一个 scale，量化后每个参数占用 1 字节，则总存储量缩小至约 70GB。

同时还需要考虑 KV 缓存的存储量。  
所以容量检查实际上是：

$$
M_W + M_{state} + M_{work} \leq M_{cap}
$$

其中 $M_W$ 是权重与量化产生的附加数据， $M_{state}$ 是请求的上下文状态， $M_{work}$ 是工作区，$M_{cap}$是加速器可用的存储容量。
