## 推测解码

### 草稿，验证，回退与正确性

推测解码，又称投机解码  
指 decode 过程中，为同一个请求，先生成一段草稿序列，再由目标模型同时验证多个 token 的方法。

对于贪心生成，每一步都选择目标模型给出的概率最高的 token。  
从第一个不一致 token 开始，之前的 token 全部保留，之后的 token 全部舍弃，重新生成。

随机采样时，设目标分布为 $p(x)$，草稿分布为 $q(x)$。  
从 q 中采样得到草稿 token x，接受的概率为：
$$
\alpha(x) = \min\left(1, \frac{p(x)}{q(x)}\right)
$$  
所以采样到 x 并接受的概率为：
$$
p(x)\alpha(x) = \min(p(x), q(x))
$$

### 每轮耗时与输出数量

设第 r 轮耗时为 $T_r$，输出 $N_r$ 个 token，平均每个 token 耗时为：
$$
\bar{t}_{spec} = \frac{\sum_{r} T_r}{\sum_{r} N_r}
$$

设各 token 位置独立，每轮草稿生成 4 个 token，  
前面的草稿 token 都被接受时，当前位置的接受概率为 a，  
每轮至少输出一个 token，则每轮平均输出数为：
$$
\mathbb{E}[N] = 1 + a + a^2 + a^3 + a^4 = \frac{1 - a^5}{1 - a}
$$

### 草稿来源与串行，并行生成方式

草稿可以直接从上下文查找，也可以调用额外的网络生成。

上下文查找从输入或已有回答中寻找重复片段，主要开销是匹配和建立索引。  
使用独立小模型生成草稿，需要额外保存权重和 KV，也需要额外的推理时间。
