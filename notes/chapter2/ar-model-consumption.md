## 自回归生成的资源消耗计算

### Prefill, Decode 与状态复用

prefill 阶段，模型得到已知输入，同时计算多个 token 的表示。  
由最后一个 token 的 logits 得出第一个输出 token，就进入了 decode 阶段。

decode 阶段，每次把上一次生成的 token 作为输入，计算下一个 token 的表示。  
所以 prefill 和 decode 使用同一个模型，前者已有多个已知输入，后者每次只有一个新输入。

Qwen3-8B 的 BF16 KV，每个上下文 token 占用：

$$
c_{KV} = 2Ln_{KV}d_hb_{KV} = 2 \times 36 \times 8 \times 128 \times 2\ bytes = 144 KiB
$$

其中第一个 2 表示键和值，$L$ 是层数，$n_{KV}$ 是每层 KV 的头数，$d_h$ 是每个头的宽度，$b_{KV}$ 是每个 KV 元素占用的字节数。

因此 Qwen3-8B 保存 $H = 8192$ 个上下文 token 的 KV 缓存需要：

$$
M_{KV} = Hc_{KV} = 8192 \times 144 KiB = 1.125 GiB
$$

当 batch 增加时，每条独立请求都要额外增加一份上下文。

### 内存占用与数据访问量

按用途和生命周期，数据可以分为以下三类：

| 数据类别   | 存储与复用                         | 需要计算的主要项目                                 |
| ---------- | ---------------------------------- | -------------------------------------------------- |
| 权重       | 通常在多次调用间保持不变           | 常驻字节，被访问的权重集合，批内复用               |
| 上下文状态 | 随请求保留，持续追加或更新         | 实际占用的容量，每部读写量，更新所需的计算         |
| 临时数据   | 在相应算子或阶段中产生，使用后释放 | 张量尺寸，经过存储接口的数据量，需要同时保存的部分 |

### 生成完整回答的计算量与状态读写量

假设 $B = 1$，已恢复前缀为 $S$，输入 $P$ 个 token，需要返回 $G$ 个 token，令上下文 $H = S + P$。  
prefill处理新输入并产生首个输出，随后执行 $n_d = G - 1$ 次 decode。  
最终返回的 token 尚未重新送入模型，因此请求结束时不为它保存 KV。

第 $j$ 次 decode 时，上下文长度为 $H + j$，若每次 decode 都将此前的上下文读取一遍，累计读取量为：

$$
R_{old} = c_{KV} \sum_{j=0}^{n_d-1} (H + j) = c_{KV} \left[ n_d H + \frac{n_d(n_d + 1)}{2} \right]
$$

最终有效的 KV 存储量为 $ c_{KV} (H + n_d) $

因此逐步生成的情况下，KV累计读取量远超存储量。

线性投影与FFN的在每次 decode 都只处理一行，上下文交互随 $H + j$ 线性增长。  
设每步固定的矩阵运算量为 $F_0$，而每次与上下文 token 交互需要的运算量为 $a$，则 decode 阶段的总计算量为：

$$
F_{decode,total} = n_d F_0 + a \left[ n_d H + \frac{n_d(n_d + 1)}{2} \right]
$$

输出变长时，固定部分工作量线性增长，上下文部分平方增长。
