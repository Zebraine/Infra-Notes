## 上下文状态表示与访问机制

模型处理上下文后保存下来，供后续计算复用的表示，称为 **上下文状态**。

### 多头注意力与 KV 共享

逐 token 记录最直接的节省办法，是减少每个 token 保存的 K,V 份数。  
多头注意力(MHA)，每个 Q 头对应一个 K,V 头。  
多查询注意力(MQA)，所有 Q 头共享同一组 K,V 头。  
分组查询注意力(GQA)，每组 Q 头共享一组 K,V 头。

共享 K，V 改变了被查询的数据，但是 32 个 Q 头仍然需要分别计算分数和加权求和。  
所以 $QK^T$ 和 $AV$ 计算仍然会随查询头数线性增长。

实际工程中选择 GQA，是为了避免 MQA 带来的训练不稳定与性能下降。

### 潜变量压缩与 MLA 执行路径

多头潜变量注意力(MLA)通过降低上下文表示的维度，节省空间。  
先把输入投影投影为低维潜变量 $c$，再经过上投影得到用于计算注意力的 $K,V$。  
模型在训练过程中需要学习这些低维表示和上投影，在生成过程中则只需要将上下文以 $c$ 的形式保存下来。  

假设键的上投影为 $U_k$，上下文潜变量按行组成矩阵 $c$，展开键为 $K = c U_k$，则注意力计算为：
$$
qK^T = q (c U_k)^T = (q U_k^T) c^T
$$  
根据结合律将 $q U_k^T$ 提前计算，实现矩阵吸收，在计算过程中的最高维度就从 $d$ 降低到 $d_c$，节省了计算量。  

不过 MLA 也会的矩阵吸收无法应用于 RoPE，转置后两个旋转矩阵会夹在 $q$ 和 $U_k^T$ 之间，无法提前计算。  
因此需要将 RoPE 单独处理，也就是解耦式 RoPE。  

### 局部窗口，上下文压缩与稀疏索引

**局部滑动窗口注意力**(SWA) 只读取最近的一段位置的上下文，忽略远处的上下文。  
**压缩稀疏注意力**(CSA) 通过压缩上下文，再通过索引选取相关条目。  
**高压缩注意力**(HCA) 相比 CSA 进一步压缩上下文，但不使用索引，而是使用所有压缩后的条目计算注意力。  

SWA 能够精确捕获近期的局部上下文，但无法捕获远程依赖。  
CSA 能够有选择地保留中远程依赖，但需要索引机制。  
HCA 能够捕获中远程依赖，但是会损失大量细粒度，只能保留全局的宏观语义概览。

### 线性注意力与有限状态递推

**有限状态递推** (FSR) 是一种将注意力计算转化为有限状态机的方式。  
对于每个新 token，FSR 不是将其与所有历史 token 计算注意力。而是通过维护状态矩阵 $S$，将历史 token 的信息压缩为有限状态。
具体计算方式为：
$$
S_t = S_{t-1} + k_t v_t^T,\quad o_t = q_t^T S_t
$$  
如果键宽为 $d_k$，值宽为 $d_v$，则状态矩阵 $S$ 的大小为 $d_k \times d_v$，与历史 token 数量无关。

实际的递推注意力还会引入门控与修正。

### 混合注意力的状态构成

实际模型经常结合有限状态层和全局注意力层。  
结合考虑固定递推状态与逐 token 上下文相加，得到混合结构的容量模型：
$$
M_{state}(H) = M_{fixed} + c_{state} H,\quad H_{*} = \frac{M_{fixed}}{c_{state}}
$$  
其中 $c_{state}$ 是每个上下文 token 增加的状态字节数。
