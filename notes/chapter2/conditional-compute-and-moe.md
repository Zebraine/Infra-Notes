## 条件计算与专家权重复用

### 稠密前馈网络与专家路由

典型的 MoE 模型先从输入计算路由分数，按 top-k 选择专家，最后将 token 送入专家，并按路由分数加权输出。  
有共享专家时，还会有一条所有 token 都参与的分支。

参考 Qwen3,6-35B-A3B，隐藏维度 2048，每层 256 个专家，每个 token 选 8 个，专家中间维度 512。
设专家 $e$ 收到了 $t_e$ 个 token，可得  
gate/up 部分计算量是 $[t_e, 2048] \times [2048, 512]$，down 部分计算量是 $[t_e, 512] \times [512, 2048]$，  
因此主要矩阵运算量为 $6t_e \times 2048 \times 512$

用 $E$ 表示专家总数，$k_{top}$ 表示每个 token 选中的专家数，单个专家的参数量为 $N_e$，每层保存的专家参数量为 $M_{expert} = E N_e$。  
单个 token 执行的专家矩阵工作约为 $2 k_{top} N_e$。

### 实际运算量与批内权重读取量

实际用到的专家数，与选中的专家的总体分布有关。  
设有 $B = 64$ 条请求，每条执行一步 decode，每条请求输入一个 token。  
由于每个 token 选中 $k_{top} = 8$ 个专家，若均分这 512 次选择，则每个专家接收 2 个 token，此时当前batch就会访问全部 256 个专家权重。  
若全部集中到一组 8 个专家，则只会访问 8 个专家权重。

设 batch 实际访问的不同专家数为 $U$，则有 $\sum_e t_e = B k_{top}$，因此有：

$$
F_{expert} = 2 N_e \sum_e t_e = 2 N_e B k_{top},\quad R_{expert} = b_W N_e U
$$

### 共享专家与潜空间计算

DeepSeek V4-Flash 每层 256 个专家，每个 token 选择 6 个，还有 1 个共享专家。  
前三层采用哈希路由，后续采用评分路由。  
哈希路由直接根据 token 确定专家，评分路由根据 token 的表示计算路由分数，按 top-k 选择专家。

共享专家处理本次全部 $m$ 个 token 的特征向量，路由专家 $e$ 只处理分派给它的 $t_e$ 个 token。  
若共享专家有 $N_s$ 个参数，一层的专家矩阵运算量为 $2mN_s + 2\sum_e t_e N_e$。
