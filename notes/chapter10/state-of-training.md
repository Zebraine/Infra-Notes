## 训练状态的分片，重计算与卸载

### 数据并行与 ZeRO / FSDP 状态分片

SP(序列并行) 切分同一批输入的序列位置，主要作用于 TP 组中的 LayerNorm，Dropout 等逐 token 算子。  
在进入需要完整 token 行的矩阵乘时，各卡再收集输入，计算完成后按位置分片。

FSDP(全分片数据并行) 切分参数，梯度和优化器状态，这些状态分散到各卡上，需要计算某一层时临时收集参数，反向完成后再分散梯度。

ZeRO(零冗余优化器) 在数据并行的框架下，将每张 GPU 都完整存储的状态切分开，用到时再经过通信收集。  
一般分为 3 个层级：

- ZeRO-1：只切分优化器状态，参数和梯度仍然完整存储在每张 GPU 上。
- ZeRO-2：切分优化器状态和梯度，参数仍然完整存储在每张 GPU 上。
- ZeRO-3：切分优化器状态、梯度和参数，所有状态都分散到各张 GPU 上。

ZeRO-1/2 的通信开销与标准数据并行几乎相同，却得到了明显的显存节省。  
ZeRO-3 的通信开销大约是标准数据并行的 1.5 倍，但显存节省更大。

通常在内存允许的情况下，选择尽可能低的 ZeRO 层级，以减少通信开销。

### 激活的保留与选择性重计算

反向计算过程中，需要使用前向计算留下的中间激活值。  
如果显存不足，可以选择不保留部分激活值，而在反向计算时重新计算这些激活值，这种方法称为选择性重计算。

考虑矩阵运算 $Y = XW$，设损失为 $\mathcal{L}$，则反向计算为：

$$
dX = dY W^T, \quad dW = X^T dY
$$

### CPU / GPU 卸载与缓冲区的使用时间

如果重建数据的开销较小，重计算很适合。  
也可以直接保留数据本身，但是转移到容量更大的主机内存，使用时再传回 GPU，这种方式称为 卸载。

卸载是否可行，取决于数据的大小和传输速度。
