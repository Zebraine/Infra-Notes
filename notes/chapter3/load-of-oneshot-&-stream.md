## 从单次请求到持续到达的负载

### Prefill 与 Decode

负载是一定时间内到达系统，等待和执行的工作集合。  
先按时间顺序分析单个请求：  
恢复 S 个上下文 token，处理 P 个新输入，返回 G 个 token。  
调用链由一次 prefill 和 $n_d = G - 1$ 次 decode 组成。

prefill 的输入包含 BP 行，而单步 decode 只有 B 行。  
当输入 token 较多时，一次的读取可以被多个 decode 共享。  
所以 prefill 通常受算力限制，而 decode 受带宽限制。

### 任务目标与评价指标

设以下三个时间：

- $t_a$，请求到达时间
- $t_1$，首个 token 返回时间
- $t_G$，最后一个 token 返回时间

由此可以得到：

$$
T_{TTFT} = t_1 - t_a,\quad T_{request} = t_G - t_a, \quad \bar{T}_{token} = \frac{t_G - t_1}{G - 1}
$$

TTFT (time to first token) 称为首字延迟，也称为首响应。

一般需要记录以下指标：

| 问题                   | 需要的指标或记录                                   |
| ---------------------- | -------------------------------------------------- |
| 多久开始回应           | TTFT，思考模型需要额外记录首个有用输出(非思考输出) |
| 输出是否连续           | 逐 token / 逐块的间隔，及其分布                    |
| 多久完成请求           | 完整请求时间，完整任务时间                         |
| 每秒完成多少合格任务   | 在质量与时限要求下的有效吞吐                       |
| 得到一个成果结果的花费 | 全部尝试的模型，工具和环境成本 / 成果任务数        |
| 等待期间的占用         | 状态所属的请求与模型版本，大小，存放位置与驻留时间 |

在观察指标时常选用 p95 分位数，避免平均数对极端值的敏感性。  
状态在等待期间的占用也是重要指标，  
假设任务状态大小为 $M(T)$，状态占用空间对时间的积分为：

$$
A_M = \int_{t_{start}}^{t_{end}} M(t) dt
$$

### 请求分布

假设窗口内均匀到达，且处理速度稳定。  
将离散的生成工作视为连续的流，以时间窗为步长，窗口内的积压请求数为：

$$
Q_{k+1} = max(0, Q_k + A_k - \mu_k\Delta t)
$$

其中 $Q_k$ 是窗口 $k$ 的积压请求数，$A_k$ 是窗口内到达的请求数，$\mu_k$ 是窗口内的处理能力，$\Delta t$ 是窗口长度。
