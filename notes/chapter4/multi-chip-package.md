## 多芯片封装与互联

### 封装内的计算芯片，内存与连接

封装内可以包含多颗 die，这些 die 共同提供计算单元和内存接口。

die 间链路带宽与本地 HBM 带宽只比决定了实际使用上的区别。

Nvidia 的 die 间链路带宽很高，因此两颗 die 可以当作一颗 GPU 使用。  
华为 的 die 间链路带宽较低，此时应该让计算单元在本地反复使用大块权重，只在 die 之间传递较小的输入和结果。

多芯片封装还创造了并行机会，两侧本地读取和计算可以分别进行，最终再交接结果。

### CPU 与加速器之间的数据访问

芯片之间也存在和 die 间通信相同的问题。

CPU 准备的数据需要传给 GPU 使用，而 CPU 准备的输入通常在主机内存中，再由 GPU 经过 PCIe 或平台专用连接获取。  
主机到设备称为 H2D，设备到主机称为 D2H。  
实际的搬运工作由 DMA 完成，CPU 只需要发起请求。

同一份数据先经过主机链路上传，再由 GPU 从显存中读取，需要两次传输。  
上传时间一般远高于显存读取时间，所以需要在显存中多次复用，均摊上传时间。

统一内存机制可以让 CPU 和 GPU 共享同一份数据，数据交接从复制变为了同步，减少了上传时间。

### 加速器之间的数据交换

卡之间需要频繁交换激活，专家输入与其它中间结果。  
一次传输既要提交请求，通知接收方完成状态，也要通过链路传送数据。  

设固定开销 $\alpha$，有效单项带宽 R，数据量 V，则点对点时间为：
$$
T_{edge} = \alpha + \frac{V}{R}
$$
